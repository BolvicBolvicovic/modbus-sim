## Build & verification
- `make` builds `./mogbus` (clang, else gcc, else cc; ccache and mold used only when present; explicit `CC`/`LDFLAGS` win). `BUILD=dev` (or `make -j$(nproc) dev tests`) is the fast `-O0` variant with separate `.dev.*` objects; CI uses prod.
- `WITH_TLS=auto|1|0` (auto: only if `pkg-config --exists openssl`); `WITH_CONFIG=0` builds only the libraries and drops config, the binary and the tests that need them. `make WITH_TLS=0 tests`, `make WITH_CONFIG=0 tests` and `make WITH_CONFIG=0 WITH_TLS=0 tests` must stay green.
- `PLATFORM=win32` cross-builds with MinGW-w64 (`make PLATFORM=win32 WITH_TLS=0`, tests run under Wine). Keep CI job `windows-cross` (`tools/win32_check.sh`) green when touching `src/os`, sockets or the Makefile. See `docs/user/windows/windows-route.md`.
- `make lib` builds `libmogbus.a`/`.so`; `make lib-check` builds the examples against both with only `-Iinclude` and fails if the `.so` exports anything but `mogbus_*`. `include/mogbus.h` is the only API surface. `make tests` depends on `lib-check`, which also runs `tools/check_install.sh` (`make install` into a temporary `DESTDIR`, builds `examples/embed_tcp.c` through `pkg-config --cflags --libs mogbus`, shared and `--static`, checks `make uninstall`). `make install [PREFIX=/usr/local] [DESTDIR=]` installs `bin/mogbus`, both libraries (soname stays `libmogbus.so` until 1.0), the header, `lib/pkgconfig/mogbus.pc`, profiles and user docs; `make dist` stages its tarball through the same target (`PC_RELOCATABLE=1`), so keep both in step.
- `make python` / `make python-tests` / `make python-examples`: `python/` is a ctypes-only package; struct layouts in `python/mogbus/_lib.py` must match `include/mogbus.h` (checked by `python/tests/layout.c`). Keep Python in sync with every public API change. asyncio (`Server.serve`, `Context.serve_all`, `AsyncClient`) steps on the loop using `mogbus_server_poll_fds`/`mogbus_poll_fds`; `AsyncClient` must mirror `Client` (checked by `python/tests/test_asyncio.py`).
- Builds are bit-for-bit reproducible (`tools/check_reproducible.sh`): keep `REPRO_FLAGS` (`-ffile-prefix-map`) on every shipped compile, sorted source lists, `ar rcsD`, no `__DATE__`/`__TIME__`/clock/absolute paths in artifacts, git revision only in `src/main.c`.
- `make tests` picks scopes with `WHAT` (`c`, `python`, `docs`, `all`, `auto`; `auto` by changed files locally, `c` when `CI` is set); `SUITES=obs,pdu` narrows the `c` scope. Use `WHAT=all` before pushing.
- CI-equivalent checks: `make`, `make tests`, `for p in profiles/*.scm; do ./mogbus --check "$p"; done` (also with `WITH_TLS=0`), `make asan` (`detect_leaks=0` is intentional), `make docs` + `tools/check_docs.sh examples ./mogbus`, and scan-build as CI runs it: `make clean && make -j$(nproc) third_party/s7/s7.o && scan-build --status-bugs --use-cc clang --exclude third_party/s7 -o scan-output make -j$(nproc)` (no ccache, no mold). `make fuzz` / `make fuzz-run FUZZ_SECONDS=N` run the libFuzzer harnesses in `tests/fuzz/`.
- `./mogbus --check <config.scm>` validates a config silently (`--check=verbose` prints the summary). Keep every profile passing in TLS and no-TLS builds when changing config parsing or device behavior.
- CI input rule: `ci.yml` path filters and `tools/changes.sh` (one file-to-category table for CI and `make tests` auto scope) decide what runs. When adding a top-level file/directory the build reads, add it to both.
- After every push, check CI (`gh run list`/`gh run watch`) and fix what fails. GitHub issues are handled only when the user names one.

## Focused tests
- `./mogbus-tests --list`; `./mogbus-tests -s <suite> -t <test>`; `make tests WHAT=c SUITES=obs`; `make tests WHAT=python`.
- Do not trust a whole-suite run of the vtest binary: it exits 0 even on failure. `tools/run_tests.sh` runs each test in its own process, in parallel, and fails correctly. Integration tests must use free ports (`ts_free_port`) and never share fixed resources, since any two tests may run at once. `MOGBUS_BIN=/path ./tools/run_tests.sh ./mogbus-tests` overrides the binary.
- After touching locking, also run `tests/threads.c` under `-fsanitize=thread`.
- After doc/theme changes that look stale, `rm -rf build/docs && make docs` (must be warning-free, no broken links).

## Architecture
Dependency direction: `server -> net -> modbus -> device -> util -> os`; every layer may include `os/`; `net -> webui`; `config -> device -> util`; `server_config -> server, config`; `client -> modbus, util, os` (plus `net/net_tls.h` for TLS); `view -> device, util, os`; `decode -> modbus, util, os`; `api` is the top layer. `src/main.c` includes only `mogbus.h` and is a pure client of the public API. Only `src/os/*` may include OS headers (`tools/check_deps.sh` enforces all of this).

Where things are (and what is easy to break):
- Transports `src/net/*_server.c` (tcp, rtu, ascii, rtu-tcp, ascii-tcp, udp, rtu-udp, ascii-udp): caller-owned structs with `init/step/stop/close`, no globals, no signal handlers. Poll only through `net_poll()` and record requests via `net_handle_pdu()`/`net_obs_request()`. Shared code: `net_tcp_pool`, `net_udp`, `net_mbap_respond`, `net_tls`/`net_tls_stub`. Listeners and UDP sockets bind `127.0.0.1` by default; `0.0.0.0` is explicit opt-in. Semantics per mode: `docs/user/transports/`.
- PDU dispatch `src/modbus/pdu.c`; RTU CRC/framing `rtu.c`, ASCII `ascii.c`. The supported FC list is intentional (see `docs/user/modbus/`); other FCs get exception 01 unless user-defined. Faults never change request processing (`docs/user/config/faults/`).
- Devices `src/device/`: only configured points exist; an undefined address returns exception 02 by design. `device_tick` is computed at request time (no background thread). `device_write()` is the host path; Modbus clients go through `device_client_write()` (read-only points).
- Hooks (access, written, frame) run only on the Modbus client path, never on host writes (`docs/user/library/library-hooks.md`).
- Point actions (`on-read`/`on-write`, `src/device/action.c`, compiled by the machine compiler) run on the Modbus client path inside the server step with the context lock held: no allocation, no blocking, never on host writes; parameters change via `mogbus_device_set_action_param`. See `docs/user/config/actions/`.
- Config `src/config/` reads Scheme as data (s7 `read`, never eval); only `server_config.c` adapts `config_t` to the server facade. Config keys: `docs/user/config/`.
- Server facade `src/server/server.{h,c}` is config-independent. Several servers per context share one arena and one `os_wait` (`docs/user/config/server/id.md`).
- Public API `src/api/mogbus.c` + `include/mogbus.h`; value helpers `src/api/value_api.c` (`mogbus_registers_to_value` and friends, no context, reuse `device/encode.c`, Python `registers_to_value`/`value_to_registers`/`registers_to_text`/`text_to_registers`, tests `tests/value_api.c`, `python/tests/test_values.py`); client (master) `src/client/` + `src/api/client_api.c` (TLS over `net_tls`, host names through `os_resolve`, byte timeouts); `--health` is `src/api/probe.c`; register view `src/view/` (drawn by `mogbus_step()`); frame decoder `src/decode/` (`mogbus --decode`, `mogbus_decode_frame`, Python `decode_frame`; no context, no lock, no allocation; tests `tests/decode.c`, `tests/decode_cli.c`, fuzz `tests/fuzz/fuzz_decode.c`; keep it in step with every function code the PDU layer supports, see `docs/user/modbus/decoding-frames.md`).
- Observability and HTTP `src/net/net_obs.c`, control API `src/net/net_control.c` (also reachable through `net_obs_http_feed()`, fuzzed by `tests/fuzz/fuzz_http.c`).
- Web UI `src/webui/index.html`: one self-contained file embedded as `page_data.h` (generated, gitignored); DOM text only via `textContent`; `tests/obs.c` checks its main element ids. See `docs/user/observability/web-ui.md`.
- Python `python/` (ctypes), importer `tools/mogbus_import.py`; docs site `tools/docs/` + `docs/site.json`.
- Thread safety is always on: each public `mogbus_*` function that takes a context, device or server starts with `LOCK(ctx)` in `src/api/mogbus.c`. New blocking waits in a transport go through `net_poll()` (releases the lock). `mogbus_stop` and the signal helpers never lock. See `docs/user/library/library-lifetimes.md`.

## Repo constraints
- Plain C (gnu11), Linux first plus the MinGW-w64 Windows build of the network modes; OS calls (`poll`, `accept4`, termios, PTY, signals) stay in `src/os/`. Warnings are errors (`-Wall -Wextra -Werror -Wformat=2 -Wshadow`, hardened flags); keep all builds clean.
- No `malloc/free/new/delete` in project code: use vlib arenas (`ARENA_*`). `ARENA_IMPL` is defined only in `src/util/arena_impl.c` and `vlib/vtest.c`. Request handling must not allocate. `src/main.c` owns no arenas.
- `third_party/s7` is vendored and `vlib/` is a git submodule: never modify either, never "fix" warnings there (vlib changes go upstream to BolvicBolvicovic/vlib, then bump the pin).
- `src/*.c` (recursive) and `tests/*.c` are picked up by the Makefile automatically.

## Style & scope
- Smallest change that solves the task; avoid unnecessary abstraction, not optimization.
- A fallible function reports failure through its return value only (status enum, bool for a single reason, NULL for an internal constructor), never through an extra error-message or status out-parameter. The owner keeps the message (context via `mogbus_last_error(ctx)`, internal structs such as `config_t`, or a log). Every fallible public `mogbus_*` function returns `mogbus_result_t`; constructors return the object through a last `T** out` that is NULL on failure. Plain accessors that cannot fail keep their natural return value. Python raises `MogbusError`.
- Prefer fat structs; define a small struct used by one bigger struct inside it.
- Functions may be long; inline single-use helpers and tiny reused ones when clear.
- Conditions with three or more sub-conditions: one per line, operator at line end, continuation indented 4 spaces past the `if` (a parenthesized group is one sub-condition).
- Prefer enums over `#define` for related constants; bit flags use `BITn` from `vlib/bits.h` (never `BIT31`). No `is_` prefix when the name is clear.
- Comments only for non-obvious logic or easy-to-miss constraints. Doxygen rules are in `docs/dev/architecture.md` and `docs/dev/docs.md`; what `make docs`/`tools/check_docs.sh briefs` enforce: `/** @file @brief */` per source file, a brief on every file, struct, union, enum and typedef; full `@param`/`@return` only in `include/mogbus.h`. Group forward typedefs at the top after the includes, never `typedef struct x_t {...} x_t;`, brief directly above the `struct x_t {`. `make docs` must stay warning-free.
- Markdown links between pages are relative `.md` links; links to non-page files (profiles, sources, directories) are absolute `https://github.com/BolvicBolvicovic/mogbus/blob/main/...` URLs. Every page must be listed in `docs/site.json`. Reference entries follow the template in `docs/dev/docs.md`. Python docstrings in `python/mogbus/core.py` are Doxygen comments.
- Behavior changes update the docs (`README.md`, `AGENTS.md`, `docs/`). `docs/user/` is for people who run, configure, embed or deploy mogbus (ships in the tarball; no build/CI internals); `docs/dev/` is for contributors. `docs/dev/roadmap.md` lists only outstanding work: remove an item when done and document it in its proper page.
- In reviews, check tests against intended behavior/spec; do not accept tests weakened to fit an incorrect implementation.
