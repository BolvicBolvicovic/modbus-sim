# AGENTS.md

## Build & verification
- `make` builds `./mogbus` (`src/main.c` linked against the same-variant static library: `libmogbus.a` in prod, `libmogbus.dev.a`/`libmogbus.notls.a`/... otherwise, all removed by `make clean`) with `clang` by default (falling back to `gcc`, then `cc`) and the default linker, adding a `ccache` prefix when installed and `-fuse-ld=mold` only when mold is installed and the compiler accepts it; explicit `CC`/`LDFLAGS` overrides still win, and hardening linker flags `-pie -Wl,-z,relro,-z,now` are appended unless already present. `WITH_TLS` defaults to `auto`: TLS is enabled only when `pkg-config --exists openssl` succeeds, so serial/RTU/ASCII/plaintext-TCP builds work without OpenSSL. `WITH_TLS=1` fails early with a clear error if `pkg-config` or OpenSSL development files are missing; `WITH_TLS=0` never passes OpenSSL cflags/libs and compiles `src/net/net_tls_stub.c` instead of `src/net/net_tls.c`. `src/build_config.h` defines the `WITH_TLS` fallback for direct compiles; config loading rejects `(tls ...)` in no-TLS builds with `built without TLS support`. `WITH_CONFIG` defaults to `1`; `WITH_CONFIG=0` skips `src/config/*`, `src/server/server_config.c`, `src/main.c` and s7 (objects tagged `.nocfg`), builds the libraries instead of the binary (`make`/`all` = `lib`), leaves `mogbus_load_config`/`mogbus_server_create_from_config` failing with `built without config support`, and `make WITH_CONFIG=0 tests` excludes the test files that need config or the binary (`tests/config.c`, `*_cli.c`, `tcp_server.c`, `*_tcp_server.c`, `udp_server.c`, `*_udp_server.c`, `machine_e2e.c`) and skips `check_toolchain.sh`; `src/build_config.h` has the `WITH_CONFIG` fallback.
- `BUILD=dev` builds project code at `-O0` without `_FORTIFY_SOURCE` into separate `.dev.*` objects for faster iteration; default `BUILD=prod` remains the hardened `-O2` build used by CI. The vendored s7 parser is always `-O0` because it only parses config at startup. `make -j$(nproc) dev` sets `BUILD=dev` with the default toolchain and forwards extra goals such as `make -j$(nproc) dev tests`.
- `PLATFORM=win32` (default `posix`) cross-compiles a native Windows build with MinGW-w64 (`CROSS=x86_64-w64-mingw32-` prefix, default CC `$(CROSS)gcc`, objects tagged `.win32`): `make PLATFORM=win32 WITH_TLS=0` builds `mogbus.exe` (static, `--dynamicbase --nxcompat --high-entropy-va`), `libmogbus.win32.a`, `mogbus.dll` (+ `libmogbus.dll.a`, `MOGBUS_BUILD` selects `dllexport` in `MOGBUS_API`) and `mogbus-tests.exe`; it uses `src/os/os_*_win32.c` (Winsock 2, `WSAPoll`; serial/PTY/`*_fd` are an honest stub) and `-Wno-format` (MinGW's `printf` attribute is the MSVCRT dialect; Linux keeps the format checks). TLS stays off on Windows. The tests listed in `TESTS_POSIX_ONLY` (fork, PTY, termios, POSIX sockets, `test_support.c`) are left out of `mogbus-tests.exe`; `make PLATFORM=win32 tests` runs the rest under Wine through `RUN_TESTS_WRAPPER` (`tools/run_tests.sh` strips the CRs). `lib-check`, `check_toolchain.sh`, `dist`, python and reproducibility stay Linux-only. `tools/win32_check.sh` (CI job `windows-cross`, `PYMODBUS=1` adds the interop) builds, runs the unit tests under Wine and checks `mogbus.exe` in all six network modes with the native `--health`, `modbus_probe.py` and pymodbus; keep it green when touching `src/os`, sockets or the Makefile. See `docs/user/windows/windows-route.md`.
- `make lib` builds `libmogbus.a` (all project objects plus s7 and `src/util/arena_impl.c`) and `libmogbus.so` (`-shared -Wl,-soname,libmogbus.so`, `-pie` filtered out of `LDFLAGS`, relro/now kept, linked with `$(LIBS)`) from the same objects as the binary; `make`/`all` still builds only `./mogbus`. `make lib-check` builds `examples/embed_tcp.c` and the tutorial program `examples/tutorial/pump_station.c` (`--self-test`, plus `--config profiles/two-devices.scm --unit 10` when `WITH_CONFIG=1`) with only `-Iinclude` against both libraries (`.so` via rpath `$ORIGIN/..`, `$ORIGIN/../..` for the tutorial), fails if `nm -D --defined-only libmogbus.so` shows anything but `mogbus_*` (plus linker `_init`/`_fini`/`_edata`/`_end`/`__bss_start`), and runs every example against both libraries; `make tests` depends on it. Project and s7 objects use `-fPIC -fvisibility=hidden` (not `-fPIE`; PIC is valid in the PIE binary), and the public header `include/mogbus.h` is the only API surface (`MOGBUS_API` exports). The test binary leaves `src/util/arena_impl.o` out because `vlib/vtest.c` has its own `ARENA_IMPL`. See `docs/user/library/library-start.md`.
- `make python` builds `libmogbus.so` and copies it to `python/mogbus/` (gitignored); `make python-tests` runs `python3 -m unittest discover -s python/tests` against the built library via `MOGBUS_LIB`. `python/` is a `ctypes`-only package (`mogbus/_lib.py` loads the library and declares the C structs/signatures, `core.py` is the API; one `RLock` per context is kept on top of the thread-safe C library because it also guards the package's own state (closed handles, hook registries, the stepping thread), and `Server.start()` steps on a background thread). Keep it in sync with `include/mogbus.h` (struct layouts live in `_lib.py`; a test compares the `ServerOptions` defaults with the C ones). `examples/python/embed.py`, `pump_station.py` (the Python tutorial) and the unittest `test_pump_station.py` run in CI through `make python-examples` (the pytest files `conftest.py`, `test_device.py`, `test_station.py` do not; pytest is not a dependency). The docstrings of `python/mogbus/core.py` are Doxygen comments rendered as the Python API reference by `tools/docs/build.py` (every public name needs `@brief`/`@param`, see `docs/dev/docs.md`). `tools/mogbus_import.py` (stdlib-only CSV/pymodbus importer, `docs/user/import/import-overview.md`, examples in `examples/import/` with committed `.scm` outputs) is tested by `python/tests/test_import.py` (needs `./mogbus` for the `--check` cases, so the CI `python` job builds the binary). CI job `python`; `python/**` is a CI input in `ci.yml` and `tools/ci_changes.sh`. See `docs/user/python/python-start.md`.
- `make dist` (prod only) builds and writes `dist/mogbus-<version>-linux-<arch>.tar.gz`, `.spdx.json` (via `tools/gen_sbom.sh`, plain shell) and `SHA256SUMS`; `make clean` removes `dist/`. `.github/workflows/release.yml` (tags `v*`, must equal `MOGBUS_VERSION_*` in `include/mogbus.h`; `workflow_dispatch` is a dry run) builds x86_64 and aarch64, runs tests, publishes the release and attests provenance; pin new actions by commit SHA. See `docs/dev/release.md`.
- Builds must stay bit-for-bit reproducible (`tools/check_reproducible.sh`, CI job `reproducible`): the check copies `git ls-files -c --recurse-submodules` (so vlib is included) and passes the vlib commit to `tools/gen_sbom.sh` as `VLIB_REVISION`; keep `REPRO_FLAGS` (`-ffile-prefix-map`) on every compile of shipped objects, sorted source lists, `ar rcsD`, no `__DATE__`/`__TIME__`/clock or absolute paths in artifacts, and the git revision (`MOGBUS_GIT_REVISION`) only in `src/main.c`. `mogbus --version`/`-V` prints `mogbus X.Y.Z (<revision>)`.
- `make tests` runs the scopes picked by `WHAT` (comma-separated `c`, `python`, `docs`, `all`, `auto`; unknown values fail listing the valid ones). `WHAT` defaults to `auto` locally and to `c` when the `CI` environment variable is set (GitHub sets it), so every CI `make tests` step keeps running the full C suite; CI is the only place that runs everything (the `python` and `docs` jobs keep their own targets). `auto` (`tools/test_scope.sh`, POSIX sh, `--self-test`, prints the chosen scopes and why) maps the files changed versus the merge base with `origin/main` plus uncommitted and untracked ones: C sources/headers, `Makefile`, `src/`, `tests/`, `include/`, `profiles/`, `vlib`, `third_party/s7`, build/test `tools/*.sh` -> `c`; `python/`, `tools/mogbus_import.py`, `examples/python/`, `examples/import/`, `include/mogbus.h` -> `python`; `*.md`, `docs/`, `Doxyfile`, `tools/docs/`, `tools/check_doc_briefs.sh`, `tools/check_doc_examples.sh` -> `docs`; no recognised change or no git/`origin/main` -> `c`. Scopes: `c` is the full C run below, `python` is `make python-tests python-examples` (plus the binary for the import `--check` cases), `docs` is `make docs` plus `tools/check_doc_examples.sh`; `python` and `docs` need `WITH_CONFIG=1`. `SUITES=obs,pdu` (vtest suite names, file stem or `tests/obs.c`; empty = all; unknown names fail) limits the `c` scope through `RUN_TESTS_SUITES` in `tools/run_tests.sh`.
- The `c` scope builds `./mogbus` (needed by integration tests) and `./mogbus-tests`, then runs the tests through `tools/run_tests.sh`.
  - Do not trust a plain whole-suite run of the vtest binary for pass/fail: vtest exits 0 for whole suites even on failure. `tools/run_tests.sh` runs each test individually and fails correctly. Tests run one per process in parallel with `RUN_TESTS_JOBS` workers (default `nproc`, via `xargs -P`), slowest first using the previous run's durations in `BIN.times` (gitignored, removed by `make clean`); integration tests must pick free ports (`ts_free_port`) and never share fixed resources, since any two tests may run at once.
- `make fuzz` builds libFuzzer harnesses `tests/fuzz/fuzz_*.c` (clang `-fsanitize=fuzzer,address,undefined`, compiled directly from `src/modbus`, `src/device`, `src/util` and a few `src/net` files into `build/fuzz/`); `make fuzz-run FUZZ_SECONDS=N` seeds and runs each (`tools/run_fuzz.sh`; harnesses run in parallel, at most `FUZZ_JOBS` at once, default `nproc`, results printed in a stable order; CI job `fuzz` at 30 s per push with `build/fuzz/corpus` persisted through `actions/cache` keyed `fuzz-corpus-<run_id>` with `restore-keys: fuzz-corpus-`; `.github/workflows/fuzz-nightly.yml` runs 600 s daily on the same cache and opens or comments on the issue "Nightly fuzzing found a crash" on failure). New `tests/fuzz/fuzz_NAME.c` files are picked up automatically; keep harness invariants true to the spec (e.g. CANopen extended exceptions are longer than 2 bytes). `tests/robustness.c` covers garbage and fragmented frames on every network transport; `tools/loadtest.py` is the load/stability tool (CI: 32 clients, 5 s); `examples/interop/pymodbus_interop.py` is the pymodbus interoperability check (CI job `interop`, pinned `pymodbus==3.8.6`).
- `make asan` builds/runs sanitizer tests (`ASAN_OPTIONS=detect_leaks=0` is intentional here; vendored `third_party/s7` is compiled without sanitizers). ASan builds include `float-cast-overflow`.
- CI-equivalent checks: `make`, `make tests`, `for p in profiles/*.scm; do ./mogbus --check "$p"; done`, `make asan`. The no-TLS job runs `make WITH_TLS=0`, `make WITH_TLS=0 tests`, the same profile checks and `tools/check_doc_examples.sh` without installing OpenSSL, plus `make WITH_CONFIG=0 tests` and `make WITH_CONFIG=0 WITH_TLS=0 tests`. CI uses the runner's clang with the Makefile defaults in the prod, no-TLS and dev jobs, installing ccache and mold in those jobs; the analyzer job installs clang-tools and uses clang `scan-build` (excluding vendored s7) with plain linker flags because its bundled clang does not accept `-fuse-ld=mold`; no GCC-only flags remain. Keep all profile checks passing in both builds when changing config parsing/validation or device behavior.
- CI runs only when code changes: `ci.yml` path filters skip pushes that touch neither code nor the files the docs job builds (`LICENSE`, `python/README.md`, ... are not watched; of the workflows only `ci.yml` itself is; `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `NOTICE.md`, `AGENTS.md` and `docs/**` are watched because they are pages of the generated site), and its first job `changes` (`tools/ci_changes.sh BASE HEAD`) skips the build/test jobs when C files changed only in comments (comparing `gcc -fpreprocessed -E` output) or only packaging files changed: `docs` runs for any C, Doxyfile, Markdown page, `docs/**` (including `docs/site.json`), Doxygen theme, `tools/docs/**` or `tools/check_doc_briefs.sh` change, `docker` for code or `Dockerfile`/`.dockerignore`/`deploy/**` changes. When adding a CI input (a new top-level file or directory the build reads), add it to both the path filters and `ci_changes.sh`.
- `./mogbus --check <config.scm>` validates a config without starting the server and prints nothing when it is valid (the error and exit status 1 otherwise); `--check=verbose` prints the summary and `config OK`. When TLS is enabled it creates (and destroys) a TLS context, so missing/mismatched files and bad ciphers fail with exit status 1 instead of printing `config OK`.
- `Dockerfile` (multi-stage: Debian trixie build stage pinned by tag and digest, `gcr.io/distroless/base-debian13` runtime stage pinned by digest with no shell/`cat`/`grep` (so checks read `/proc/<host pid>` from the host), runs as UID/GID 10001), `.dockerignore`, `deploy/docker/mogbus.scm` (container default config, binds `0.0.0.0:1502`), `deploy/docker-compose.yml` and `deploy/kubernetes/mogbus.yaml` are covered by the CI `docker` job (build, hardened run with `--read-only --cap-drop ALL`, wait for the Docker health status, register read, PID 1 uid/caps check, `docker stop` exit 0 under 8 s, `docker compose config`); no local Docker daemon is needed for anything else. When bumping the base image, update the digest (and tag for the build stage) in both `FROM` lines and the `base.name` label. See `docs/user/deployment/docker.md`.
- After every push, check CI (`gh run list`/`gh run watch`) and open GitHub issues (`gh issue list --state open`). If an open issue needs handling, finalize the current push, pause the current loop, handle issues sequentially (branch/worktree, implement/test/review/fix/reverify/merge/cleanup/push, checking CI and open issues after each push), then resume the previous loop.

## Architecture & behavior (non-obvious)
- Main flow: `src/config/*` reads the Scheme config as data (via s7 `read`, not evaluation) and builds devices. TCP (`src/net/tcp_server.c`, single-thread `poll`, max 32 clients), RTU (`src/net/rtu_server.c`, single-thread `poll` on one byte-stream fd), ASCII (`src/net/ascii_server.c`, single-thread `poll` on one byte-stream fd, CRLF-delimited frames), ASCII-over-TCP (`src/net/ascii_tcp_server.c`, single-thread `poll`, max 32 TCP clients, same CRLF framing), RTU-over-TCP (`src/net/rtu_tcp_server.c`, single-thread `poll`, max 32 TCP clients, RTU framing), Modbus UDP (`src/net/udp_server.c`, single-thread `poll` on one datagram socket, one MBAP ADU per datagram, replies to the source address), ASCII-over-UDP (`src/net/ascii_udp_server.c`, same socket layer, exactly one `:`...CRLF ASCII frame per datagram), and RTU-over-UDP (`src/net/rtu_udp_server.c`, same socket layer, exactly one RTU frame per datagram, no t3.5/t1.5 timing, frame handling via `rtu_framer_handle_frame`) decode transport frames, then dispatch PDUs through `src/modbus/pdu.c` to `src/device/*`. `src/modbus/rtu.c` owns CRC-16 and RTU frame encode/decode; `src/modbus/ascii.c` owns hex/LRC encode, decode and delimiter scanning. Dependency direction: `server -> net -> modbus -> device -> util -> os` (every layer may also include `os/`, which includes nothing else of ours; only `src/os/*` may include OS headers such as poll/socket/termios/signal/unistd/fcntl/errno, enforced by `tools/check_deps.sh`; `PLATFORM ?= posix` selects `src/os/os_*_posix.c`, `PLATFORM=win32` `src/os/os_*_win32.c`), `net -> webui` (`src/webui/` embeds the page `index.html` as a byte array generated by a Makefile rule from `src/webui/index.html` with `od` and `awk` into the gitignored `src/webui/page_data.h`; it includes only util/os headers, enforced by `tools/check_deps.sh`), `config -> device -> util` (config includes only `server/server.h` among the server headers, for `server_mode_t` and the limits; `server.h` pulls in `net/` headers transitively, `tools/check_deps.sh` checks direct includes), `server_config -> server, config`, `main -> api` (`src/main.c` includes only `mogbus.h`, checked by `tools/check_deps.sh`; it installs SIGINT/SIGTERM handling through `mogbus_stop_on_signals`), `client -> modbus, util, os` (`src/client/client.{h,c}`, see below) and `view -> device, util, os` (`src/view/view.{h,c}`, the live register view, see below) and `api -> client, server_config, server, view, config, net, modbus, device, util, os` (`src/api/mogbus.c` implements the public C API in `include/mogbus.h`; it is the top layer and nothing includes it). Each transport server is a caller-owned struct with `X_server_init/step/stop/close` plus a `run` wrapper and no global state; `src/client/` is the Modbus client (master) layer, independent of servers and contexts: `client_t` lives in its own arena (`client_new`/`client_free`), connects lazily and reconnects on the next call after an `IO` error or a stream timeout, blocks with `os_wait` deadlines, frames MBAP/RTU/ASCII over TCP, UDP or a serial line (`os_serial`), retries only timeouts, and reports failures through `client_status_t` plus `client_error()`/`client_exception()` (a failed `client_new` has no owner, so its text is per thread: `client_detached_error()`, also used by `mogbus_probe`); `src/api/client_api.c` implements the public `mogbus_client_*` calls (typed FC encoding and reply checking over `client_request`; no TLS client yet, tests in `tests/client.c` run a library server on a thread, example `examples/client_function_code.c` runs in `lib-check`, Python `Client` in `python/mogbus/core.py`); `src/api/probe.c` implements `mogbus_probe` (returns `mogbus_result_t`; with no context its message is per thread, `mogbus_last_error(NULL)`; the client side of `mogbus --health`: one FC 08 sub 0x0000 echo to the first configured device over tcp/udp/rtu-tcp/rtu-udp/ascii-tcp/ascii-udp, wildcard binds probed via loopback, TLS only connect-tested, an exception reply counts as healthy, serial/PTY/fd modes rejected with `health check needs a network mode`; no allocation, blocking with a deadline); `src/server/server.{h,c}` is the config-independent facade over all eight transports (`server_options_t`, PTY/serial open, `*_fd` modes for host-owned fds) and `server_config.c` is the only adapter from `config_t`; `src/main.c` is a pure client of the public API (linked against the variant-tagged static library, e.g. `libmogbus.dev.a`; `libmogbus.a` in prod) and keeps CLI parsing, SIGINT/SIGTERM/SIGPIPE setup (via `mogbus_stop_on_signals`), the `--check` summary and printing, and the net layer installs no handlers (see `docs/dev/architecture.md`). Headers live next to `.c` files. TCP-family listeners (`tcp`, `rtu-tcp`, `ascii-tcp`) and UDP sockets (`udp`, `rtu-udp`, `ascii-udp`) bind to
`127.0.0.1` by default; `0.0.0.0` is explicit opt-in for remote access. See `docs/dev/architecture.md`.
- Several servers: a config may hold up to 8 `(server ...)` forms, each with a unique `(id "NAME")` (optional with a single server); a device lists its servers with `(servers "a" "b")` (not `server-id`, which is the FC 17 byte), required when the file has several servers, defaulting to the only server otherwise. Unit ids are unique per server (`device_shares_server()`), listener clashes (same port/protocol or serial path) fail at load, `config_t.servers[]` holds the sections and `mogbus_config_server_count`/`mogbus_server_create_from_config_at`/`mogbus_config_server_options_at` expose them; the host assigns devices with `mogbus_device_add_server` (a server with `id` serves the devices that list it, one without `id` those that list none; `mogbus_add_device` accepts duplicate unit ids, checked at assign/create). `mogbus_step`/`mogbus_run`/`mogbus_stop` drive every server of the context in one `os_wait`; `main.c` uses `mogbus_run`, `--server ID` picks the one `--health`/`--web` use. All servers and devices share the context arena (a device may serve several servers, so it must outlive them; `docs/user/library/library-lifetimes.md`); log lines carry the server id prefix. Python: `ServerOptions.id`, `Device.add_server`. See `docs/user/config/server/id.md`, `docs/user/config/device/servers.md`.
- `src/net/net_obs.{h,c}` holds per-server metrics, the structured request log line and the HTTP `/healthz`/`/readyz`/`/metrics` endpoint (`(server (http ...))`); transports must poll through `net_poll()` and record requests via `net_handle_pdu()`/`net_obs_request()`. `--log-format json` / `mogbus_set_log_format` switch logs to JSON. The register view is a library feature: `show_registers_ms` in `mogbus_server_options_t` (10-60000, 0 = off, appended last; `(server (show-registers MS))`; Python `ServerOptions.show_registers_ms`; `server_options_t.show_registers_ms` is only carried through) opens the per-context `view_t` (`src/view/view.{h,c}`, arena-allocated at the first server creation that asks, smallest interval wins, `main.c` sets it on every server for `mogbus --show-registers[=MS]`/`-r`), which `mogbus_step()` (and so `mogbus_run()`) clamps its wait to and draws after the poll; `mogbus_run()` and `mogbus_destroy()` close it. On a terminal (`os_console_terminal()`: stdout is a tty, `TERM` not `dumb`, VT enabled on Windows; and the log format is not JSON) it draws one table with ANSI sequences, redrawn in place by moving the cursor up over the previous frame (no alternate screen, so the summary and PTY lines stay above), with a header line holding the refresh interval, achieved rate, local time and device/point counts, truncated to the terminal size with a `... N more points` line; log lines are captured by a `log_sink` into a six-line pane below the table (only when the host has not installed its own sink) and written to stderr once when the view closes (the pane is erased first). Otherwise (pipe, file, JSON) it prints every point once, then only changed ones (FNV-1a hash per point in an arena table), as text or JSON lines; tested by `tests/view.c` (renderer against a fake terminal size and the line output) and `tests/show_registers_cli.c` (the real binary on a pipe). `(http (control on))` / `http_control` (off by default, WARN at start, no authentication) enables `/api/` in `src/net/net_control.{h,c}`: JSON read/write of tables (client-write semantics except that read-only points are writable), host-side `/value` set, `GET /api/devices/{unit}/points?space=&from=&limit=` (configured points of one table with type/kind/read-only/word and byte order; paged, at most 200 per page with `next` so the 32 KB response limit is never exceeded), and runtime fault set/clear validated by `fault_check()` (shared limits with the config loader; faults persist across device restart, percent only, no schedules); it is reachable without sockets through `net_obs_http_feed()` (fuzzed by `tests/fuzz/fuzz_http.c`) and counted in `mogbus_control_requests_total`.
- Web UI: `(server (http (ui on)))`, `mogbus --web`/`-w` or `http_ui` in `mogbus_server_options_t` (Python `ServerOptions.http_ui`) serves `src/webui/index.html` (one self-contained file: device selector, per-table point list paged by 50 with decoding in JS from batched raw reads refreshed every second by default (`Refresh every` selector 10 ms-10 s kept in localStorage, achieved rate in the header chip only; a tick is skipped while one is in flight), decoded and raw writes, faults panel, and a Plot view: an SVG chart of up to 8 ticked points sampled on every refresh into per-series buffers (5 minutes, at most 30000 samples) and drawn once per animation frame over a window ending at `viewEnd` (`Live` follows now; horizontal wheel, Shift+wheel, arrow keys or the history scrollbar pan at absolute times and leave live; vertical wheel/buttons zoom 1 s-5 min; time labels are elapsed since the plot started (`m:ss`) and the `Reset` button clears the buffers and restarts at 0:00 keeping the ticked points; per-pixel-column min/max decimation; drag on the chart measures a time band with `#measure` readout), plus an `Add point` combobox (filter input and an overlay popup list of tickable options) over the paged `/points` list); DOM text only via `textContent`; `tests/obs.c` checks the served page keeps its main element ids) on `GET /` of the HTTP endpoint (bytes sent from the static array after the head, never copied into `out[]`) and implies `http_control`; `-w` without an `(http ...)` config uses 127.0.0.1:9102. `/api/` and the page check `Host` (loopback names, the specific bind address, `(http (allowed-host "NAME"))`/`http_allowed_hosts` (comma-separated, at most 8), or any IP literal when bound to a wildcard; a missing Host passes) and state-changing `/api/` requests with an `Origin` header need `http://<Host>` and `Content-Type: application/json`; `/healthz`, `/readyz` and `/metrics` are never checked. See `docs/user/observability/web-ui.md`.
- A per-device access hook (`device_t.access_fn`/`access_user`, public `mogbus_device_set_access_hook`, Python `Device.set_access_hook`) runs only on the Modbus client path in `pdu.c` (`access_read` after the range validates and before the table is read, `access_write` after the range is defined and writable (`device_range_writable()`: not read-only, not machine-driven) and before the write; FC 17 write hook first), never on host writes; a nonzero return is answered as that exception. `device_access_t.target`/`mogbus_access_t.target` (`ACCESS_TABLE`, `ACCESS_FILE_RECORD`, `ACCESS_FIFO`, `ACCESS_CANOPEN`; new fields are appended) also cover FC 14 (read hook per sub-request after the whole request validates, before the response is built), FC 15 (write hook for every sub-request after validation, before anything is written), FC 18 (after the address exists, before the read) and FC 2B/0D (once the object and range are valid; a veto is the extended failure `CE 0x08000020`, `CANOPEN_ERR_ACCESS_REFUSED`); diagnostics and identification are not covered. A second hook, the post-write notification (`device_t.written_fn`/`written_user`, public `mogbus_device_set_written_hook`, Python `Device.set_written_hook`), runs in `pdu.c` after a Modbus client write was applied (`written_table()` for FC 05/06/0F/10/16 (the masked result)/17 (write half, before the read half), and inside `write_file_record_apply` once per FC 15 sub-request with target `ACCESS_FILE_RECORD`); it never runs for vetoed, failed or host writes, runs once per device with `broadcast-execute`, and is called even when a fault then drops or corrupts the response (a `restart` fault resets the device afterwards); it returns void and may call `mogbus_device_*`. A per-server frame hook (`net_obs_t.frame_fn`/`frame_user` as `net_frame_fn`, public `mogbus_server_set_frame_hook`/`mogbus_frame_fn`/`mogbus_frame_t` (new fields appended), Python `Server.set_frame_hook` with `Frame`; adapted in `src/api/mogbus.c`, never in the config) sees every transport frame through `net_frame_trace()`/`net_frame_rx()` in `net_obs`: received frames (MBAP ADU, RTU frame with CRC, ASCII `:`...CRLF; capacities 260/256/513) before validation, copied first so a rewrite never touches the receive buffer (byte-stream RTU frames reach it only with a valid CRC, since the CRC delimits them; `rtu_framer_handle_frame` does not call it for RX, its callers do), sent frames after fault injection when built (`net_mbap_respond`, `rtu_framer_handle_frame`, the ASCII servers), not when a delayed one leaves; return 0 or above capacity (WARN) drops the frame (no processing, counters or response; the TCP connection stays open). Connection open/close is not hooked. The host builds these stores with `mogbus_device_add_file_record`/`add_fifo`/`add_canopen_object` (+ read/write/`set_fifo`, `device_set_fifo`; FIFO storage always has capacity for 31 values) and Python `Device.add_file_record` and friends (see `docs/user/library/library-hooks.md`).
- Thread safety is always on, per context: `mogbus_t` embeds one recursive `os_mutex_t` (`src/os/os_mutex.h`, pthread recursive mutex or `CRITICAL_SECTION`, caller-owned storage, no allocation) and every public `mogbus_*` function that takes a context, device or server holds it through the `LOCK(ctx)` cleanup-attribute guard at the top of its function in `src/api/mogbus.c` (hooks and callbacks run with it held; recursion lets them call `mogbus_device_*`). `net_poll()` (`net_obs_t.lock`) and `server_group_step()` (`net_poll_group_t.lock`) release it around `os_wait()` so host threads run during the wait; `mogbus_server_run`/`mogbus_run` are loops of locked steps. `mogbus_server_stop`/`mogbus_stop`/the signal helpers never lock (`os_stop_flag_t` and `net_obs_t.ready` are atomics) and a waiting step notices within 1 s. `mogbus_destroy`/`mogbus_server_close` must not race other calls, a client is one thread at a time, and log level/format/sink are process-wide (the log prefix and machine error text are `_Thread_local`). New public functions that touch a context need `LOCK(...)`; new blocking waits in a transport must go through `net_poll()`. `tests/threads.c` checks it (also run it with `-fsanitize=thread` after touching locking). See `docs/user/library/library-lifetimes.md`.
- `src/net/net_tcp_pool.{h,c}` shares listen setup, accept backoff, peer formatting, free-slot lookup, idle sweeps and the common poll-table skeleton across the three TCP transports; `src/net/net_udp.{h,c}` is the shared datagram layer for the UDP transports (bind, `recvfrom` with `MSG_TRUNC` drop of empty/oversized datagrams, `sendto`, peer text, and a fixed 16-slot table of delayed responses so the `delay` fault never blocks), reused by the ASCII/RTU-over-UDP servers with their own framing; `net_mbap_respond` in `net_common` is the MBAP unit routing/PDU/fault path shared by `tcp_server` and `udp_server`; `net_tls_conn_t` in `net_tls`/`net_tls_stub` owns the SSL handle, handshake/want flags and handshake deadline, so servers only query TLS state through `net_tls`.
- Device model: points are static, ramp, clock (`(clock FIELD)`: year/month/day/weekday/hour/minute/second/unix of the wall clock, local or `(utc on)`, integer registers only, `unix` needs 32 bits, read through `os_wall_ms()`/`os_civil_from_unix()` once per tick into `device_t.wall_ms` (`wall_fixed_ms` pins it in tests), frozen by client writes, restored by restart, no noise/degradation, not machine-drivable), model (`sine`, `lag` towards a number or point, optional `noise` and `degradation` (drift, noise growth, stuck, fail) on any numeric behaviour; stateless except lag and stuck, evaluated in `model_value()`, frozen by client writes, reset by restart; `fail-after-ms` makes `device_range_failed()` turn FC 01/02/03/04/23 and user-defined `(registers ...)` reads into exception 04 and survives writes until restart; machines cannot drive them) or machine-driven. Register types are u16/s16/u32/s32/float32/u64/s64/float64 and strings (`(type string) (length N)`, N registers of ASCII, holding/input and static only, rejected as machine targets/inputs), with `(word-order ...)` for 32/64-bit and `(byte-order little)` swapping the bytes of every register; values are f64 in ramps/models/machines (u64/s64 above 2^53 round) but a static u64/s64 integer is kept exact. 4 Modbus tables of 65536 addresses each (coil/discrete/input/holding). Only configured points exist; an address with no owner is intentionally undefined and reads/writes to undefined/out-of-table targets return Modbus exception `0x02` (not a missing implementation). `(access read-only)` (coil/holding only, rejected on input/discrete; `point_t.read_only`, `mogbus_point_t.read_only`) makes every Modbus write touching the point fail with exception `0x02`: `pdu.c` writes go through `device_client_write()` (FC 22/23 pre-check with `device_range_writable()`), while `device_write()` stays the host path (`mogbus_device_write`, HTTP control raw PUT, machines) and ignores it. `device_tick` is computed at request time (no background thread).
- Modbus support is intentionally limited to FC `01,02,03,04,05,06,07,08,0B,0C,0F,10,11,14,15,16,17,18,2B/0E,2B/0D`. The simulator itself emits exception codes `01,02,03,0B`; the remaining standard codes (`04,05,06,07,08,0A`) are available only through fault injection (`09` is reserved): `04` also via `(kind sensor-disconnect)`, the others via `(fault (kind exception) (code N))`. Fault kinds are `delay`, `drop`, `exception`, `corrupt`, `disconnect`, `restart` and `sensor-disconnect`; `(fault ...)` is repeatable with at most one definition per kind, each fires by `percent` or a non-repeating schedule (max 8 steps, canonical rules in `docs/user/config/faults/schedule.md`), `corrupt` mode is `pdu` (default), `register` or `checksum` (checksum rejected in `tcp` and `udp`, where MBAP has no checksum), and `disconnect` is valid only in `tcp`, `rtu-tcp` and `ascii-tcp` modes (it implies drop and closes the client; `udp`, `ascii-udp` and `rtu-udp` have no connection and reject it). Faults never change request processing, but they no longer only affect the response: `restart` resets device state after the response is built, and `sensor-disconnect` turns successful FC 02/04 reads into exception 04. Routing is by exact unit id, else the single device with `(any-unit on)` (`net_find_device`, `mogbus_device_set_any_unit`; replies and logs carry the request's unit, RTU/ASCII leave 0 and 248-255 unanswered). Other FCs get exception 01 unless a device defines them with `(function-code CODE ...)` (user-defined codes 1-127 that are not built in: up to 8 per device, up to 16 `(on "HEX PREFIX" ACTION)` cases matched in order on the request data, actions `reply`/`echo`/`exception`/`registers`/`no-response`, unmatched request is exception 03; built-in codes cannot be redefined; they go through the same fault, listen-only, counter and metrics handling; the `(on ...)` patterns are config-only, listed by `--check` and `mogbus_device_info`; the host can instead define a code answered by a callback with `mogbus_device_add_function_code` (`mogbus_function_fn`, Python `Device.add_function_code`): `device_custom_fc_t.fn`/`user` replace the cases, the callback writes straight into the response buffer (reply data at most 252 bytes), returns 0, an exception code 1-255 or `MOGBUS_FUNCTION_NO_RESPONSE`, anything else or a longer reply is exception 04, the request unit comes from `device_t.request_unit` set by `net_handle_pdu`, the code shares the limit of 8, cannot be removed and is listed with an empty name; see `docs/user/config/device/function-code.md`, `docs/user/modbus/user-defined-function-codes.md`). TCP uses MBAP (optionally TLS-wrapped in `mode tcp` via `(server (tls ...))`, default port 802, client certificates required by default, `(tls (handshake-timeout-ms N))` closes unfinished handshakes after N ms (default 10000) independently of idle timeout, TLS closes send a one-shot nonblocking best-effort close_notify without waiting, ungraceful drops with an empty OpenSSL error queue are treated as EOF, authenticated client subjects are logged at INFO and the configured CA is advertised to clients, no role-based certificate authorization; plaintext default stays 1502); RTU uses `[addr][PDU][CRC lo hi]` over PTY/device byte streams; RTU-over-TCP uses RTU frames over TCP sockets as an explicit separate `(server (mode rtu-tcp))` transport. `(server (mode udp))` is Modbus UDP: one MBAP ADU per datagram on a UDP socket (default port 1502, loopback bind by default), unit routing and unknown-unit exception `0B` as in `tcp`; a datagram whose protocol id is not 0 or whose MBAP length does not match the datagram size, an empty datagram and one longer than 260 bytes are dropped silently (DEBUG log); replies go to the source address; delayed responses wait in the fixed table (full table drops the response with a WARN); it accepts only `mode`, `port`, `bind` and `seed`, so `tls`, `idle-timeout-ms`, serial/RTU timing options and `broadcast-execute` are rejected at load time. `(server (mode ascii-udp))` carries ASCII over UDP: each datagram must be exactly one complete `:`...`CR LF` frame (a missing CRLF, trailing or leading bytes, or a second frame make it malformed: no reassembly, no resync, no partial-frame timeout), request semantics and the per-malformed-frame FC08 `0x000C` count are those of `ascii-tcp`, replies go to the source address (uppercase hex, one frame per datagram), empty and oversized (> 515 bytes) datagrams are dropped before decoding without counting, unit ids follow RTU/ASCII rules (1-247), and it accepts only `mode`, `port` (default 1502), `bind` and `seed`. `(server (mode rtu-udp))` carries RTU over UDP: each datagram (max 256 bytes) must be exactly one RTU frame (two frames or trailing bytes reject it whole; a rejected datagram of 4-256 bytes counts one FC08 `0x000C` error on every device), request semantics are those of `rtu-tcp` (bad CRC/unknown unit/broadcast silent, `broadcast-execute` allowed), replies go to the source address, unit ids are 1-247, and it accepts only `mode`, `port` (default 1502), `bind`, `seed` and `broadcast-execute` (`baud`, `frame-gap-ms`, `strict-t15` are rejected). ASCII uses `:` + uppercase hex `[addr][PDU][LRC]` + `CR LF` over PTY/device byte streams and, in `(server (mode ascii-tcp))`, over TCP byte streams (not MBAP/Modbus TCP); it is CRLF-delimited with no t3.5/t1.5 timing, accepts lowercase hex on RX, and malformed/bad-LRC/unknown/broadcast frames produce no response and never reach PDU dispatch. ASCII resynchronizes at a second colon before the terminator, waits for the LF when a trailing CR ends a read, ignores CR/LF/space between frames without counting errors, drops a partial frame with no byte for 1 s, and counts each rejected/undecodable frame as one FC08 `0x000C` communication error on every device. Serial ASCII ttys default to 8N1; `(server (data-bits 7) (parity even) (stop-bits 1))` selects 7E1. `ascii-tcp` accepts only `mode`, `port`, `bind`, `seed`, and `idle-timeout-ms`; serial line options and `broadcast-execute` are rejected there. FC08 `0x0003` is rejected with exception 03 so `CR LF` framing cannot be changed per device. RTU inter-frame boundaries use baud-derived t3.5 when baud is known (config or tty), `frame-gap-ms` as an explicit override, or 20 ms default fallback when baud is unknown. In baud-derived auto mode, optional `(server (strict-t15 on))` enables a best-effort intra-frame t1.5 discard heuristic for RTU byte streams only; it is never applied to RTU-over-TCP because TCP read() boundaries do not reflect UART character timing. Bad CRC, unknown RTU unit, and broadcast (0) produce no RTU response; opt-in `(server (broadcast-execute on))` executes unit-0 requests on every configured device (default off, still no response, RTU transports only (`rtu-pty`, `rtu-device`, `rtu-tcp`, `rtu-udp`) — never MBAP/TCP or ASCII, where the option is rejected at load time). Writes are all-or-nothing and only valid for coils/holding registers and configured file records (FC 21). See `docs/user/modbus/` (function code entries, `docs/user/transports/`) and the config reference in `docs/user/config/` before changing protocol/config semantics.

## Repo constraints
- Plain C (gnu11), Linux first plus the MinGW-w64 Windows cross-build of the network modes (vlib mmap/`VirtualAlloc` arenas; the OS calls `poll`, `accept4`, termios, PTYs and signals are isolated in `src/os/`). Default build prefers clang (then gcc, then cc) and the default linker, with ccache and mold added independently when available and supported, and is hardened with `-Wall -Wextra -Werror -Wformat=2 -Wshadow -D_FORTIFY_SOURCE=2 -fstack-protector-strong -fPIC -fvisibility=hidden` (s7 gets only `-fPIC -fvisibility=hidden -fstack-protector-strong` with its own relaxed flags) and linked with `-pie -Wl,-z,relro,-z,now`, plus `-fuse-ld=mold` when probed successfully; `CC`, `CFLAGS`, and `LDFLAGS` can be overridden from the environment or command line.
- No `malloc/free/new/delete` in project code; use vlib arenas (`ARENA_*`). `src/main.c` owns no arenas (the library context does); request handling must not allocate per request. `ARENA_IMPL` is defined only in `src/util/arena_impl.c` (part of the library) and `vlib/vtest.c` (the test binary excludes `arena_impl.o`). The public API allocates its context, devices and server slots from a per-context arena.
- `third_party/s7` is a vendored dependency and `vlib/` a git submodule (https://github.com/BolvicBolvicovic/vlib, pinned to a commit; `make` fails early with `vlib submodule missing` when it is not initialized; CI checkouts use `submodules: true`, and `vlib` is a gitlink path in `ci.yml` filters and `tools/ci_changes.sh`): do not “fix” style/warnings there and never modify vlib in this repo (changes go upstream as PRs to BolvicBolvicovic/vlib, then bump the pin); s7 is built with relaxed flags and excluded from sanitizers (known UBSan issue upstream in vendored version). `make commands` regenerates `compile_commands.json` via `bear` if needed.
- `src/*.c` are discovered recursively and `tests/*.c` by wildcard in the Makefile; adding files in those locations is picked up automatically.

## Style & scope
- Prefer the smallest change that solves the task; less is more. Avoid unnecessary abstraction, not optimization.
- A fallible function reports failure through its return value only: a status enum (or bool when there is a single failure reason), or NULL for an internal constructor. It never also takes an error-message out-parameter or a second status out-parameter. When a human-readable message is useful, the owner keeps it: the public API stores the message of the last failure in the context (`mogbus_last_error(ctx)`), internal layers store it in the struct they fill (e.g. `config_t`) or log it. The public API has one way only: every fallible `mogbus_*` function returns `mogbus_result_t` (`MOGBUS_OK` or a `MOGBUS_ERR_*`), and a constructor hands its object back through a last `T** out` parameter that is NULL on failure (`mogbus_create(&ctx)`, `mogbus_server_create(ctx, &options, &server)`); no public function reports failure by returning NULL or false, and there is no separate "last error code" getter. Plain accessors that cannot fail with valid handles (counts, `*_at` lookups where NULL means no such item, defaults, `mogbus_last_error`, step states) keep their natural return value. Python keeps raising `MogbusError`.
- Prefer fat structs over many small structs that are only used once inside a bigger struct. If a small struct belongs only to a bigger one, define it inside that bigger struct, e.g. `struct big { struct small { int a; }; /* other fields */ };`.
- Functions don't have to be short; they should do the job they need to do. If a small helper is only used once, prefer inlining it in the larger function. Inline tiny reused helpers when practical and clear.
- Multi-step `if`/`else if` conditions (three or more sub-conditions joined by `&&`/`||`) must be written one sub-condition per line, operator at the end of the line, continuation lines indented 4 spaces past the `if`:
  ```c
  if (a &&
      b &&
      c)
  ```
  A parenthesized group counts as one sub-condition.
- For enum-like groups of related constants, prefer enums over `#define` macros.
- Bit-flag enums use `BITn` from `vlib/bits.h` (not hex or shift literals); `BIT31` is signed overflow, so do not use it.
- Booleans don't need an `is_` prefix when the name is already clear (e.g. `log_verbose()`).
- Add comments only where logic is non-obvious or a constraint is easy to miss; do not comment routine changes. For complex behavior, add a short comment.
- Doc comments follow Doxygen (see `docs/dev/architecture.md`, Coding rules): `/** @file @brief */` at the top of every source file, `/** @brief One sentence. Details. */` above types/functions/macros, `/**< */` for members, `@name`/`@{ @}` for a comment that covers several declarations, full `@param`/`@return` for public `include/mogbus.h` functions only. Comments inside function bodies stay plain `/* */`. Do not add doc comments to self-explanatory members just for coverage. `make docs` (CI job `docs`) must stay warning-free (Doxygen 1.9.8 and newer) and free of broken links. Typedefs: group all forward typedefs (`typedef struct x_t x_t;`, enums, unions) at the top of the file after the includes, never combine `typedef struct x_t { ... } x_t;`, and put the brief directly above the `struct x_t {`/`enum x_t {` definition (anonymous enums keep their brief above them; function-pointer and opaque typedefs keep their own brief). `tools/check_doc_briefs.sh` (run by `make docs`, needs `python3`) fails for any file, struct, union, enum, opaque or function-pointer typedef without a brief. The site theme (doxygen-awesome-css) is vendored in `third_party/doxygen-awesome-css/` and `docs/doxygen/header.html` is the stock header of `doxygen -w html` plus the theme scripts; regenerate it from the current Doxygen version when upgrading Doxygen. Markdown links between pages must be relative `.md` links; links to files that are not pages (profiles, sources, directories) must be absolute `https://github.com/BolvicBolvicovic/mogbus/blob/main/...` URLs because Doxygen fails on unresolvable relative links. The logo is `docs/assets/mogbus-logo.svg` (the elk icon; `docs/assets/mogbus-wordmark.svg` is the italic name with the amber g and `docs/assets/mogbus-lockup.svg` both side by side, used by the README). The site is `build/docs/` (`make docs`): `tools/docs/build.py` (stdlib Python) renders it from Doxygen's XML (`build/docs/xml`) with the theme in `tools/docs/theme/`, and Doxygen's own HTML (source/struct browser) is `build/docs/internals/`. Every page must be listed in `docs/site.json` (a page missing from it fails the build); reference entries (one key/behaviour/fault/function code per page, listed under an `index` item) follow the template in `docs/dev/docs.md` (summary paragraph, then `Syntax`, `Default`, `Valid in`, `Behaviour`, `Errors`, `Examples`, `See also` in that order); callouts are `> **Note:**`/`> **Warning:**` blockquotes (plus `> **Summary:**`, the boxed first paragraph of every C and Python tutorial step page, which also serves as the page summary); `make docs-fixtures` builds the template fixtures (`tools/docs/fixtures/`, never shipped).
- `docs/dev/roadmap.md` lists only outstanding work: when a roadmap item is done, document it in its proper page and remove it from the roadmap.
- When behavior changes or a new user-facing/config/protocol behavior is added, update the relevant docs (`README.md`, `AGENTS.md` and `docs/` as applicable) instead of adding explanatory comments everywhere. `docs/user/` is for people who run, configure, embed or deploy mogbus (config reference, profiles, Modbus support, library API, deployment) and ships in the release tarball; `docs/dev/` is for contributors and maintainers (architecture, release process). Keep build internals, CI and release mechanics out of `docs/user/`.
- In reviews, inspect tests against intended behavior/spec; do not accept tests weakened or adapted to fit an incorrect implementation.
