# AGENTS.md

## Build & verification
- `make` builds `./mogbus` (`src/main.c` linked against the same-variant static library: `libmogbus.a` in prod, `libmogbus.dev.a`/`libmogbus.notls.a`/... otherwise, all removed by `make clean`) with `clang` by default (falling back to `gcc`, then `cc`) and the default linker, adding a `ccache` prefix when installed and `-fuse-ld=mold` only when mold is installed and the compiler accepts it; explicit `CC`/`LDFLAGS` overrides still win, and hardening linker flags `-pie -Wl,-z,relro,-z,now` are appended unless already present. `WITH_TLS` defaults to `auto`: TLS is enabled only when `pkg-config --exists openssl` succeeds, so serial/RTU/ASCII/plaintext-TCP builds work without OpenSSL. `WITH_TLS=1` fails early with a clear error if `pkg-config` or OpenSSL development files are missing; `WITH_TLS=0` never passes OpenSSL cflags/libs and compiles `src/net/net_tls_stub.c` instead of `src/net/net_tls.c`. `src/build_config.h` defines the `WITH_TLS` fallback for direct compiles; config loading rejects `(tls ...)` in no-TLS builds with `built without TLS support`. `WITH_CONFIG` defaults to `1`; `WITH_CONFIG=0` skips `src/config/*`, `src/server/server_config.c`, `src/main.c` and s7 (objects tagged `.nocfg`), builds the libraries instead of the binary (`make`/`all` = `lib`), leaves `mogbus_load_config`/`mogbus_server_create_from_config` failing with `built without config support`, and `make WITH_CONFIG=0 tests` excludes the test files that need config or the binary (`tests/config.c`, `*_cli.c`, `tcp_server.c`, `*_tcp_server.c`, `udp_server.c`, `*_udp_server.c`, `machine_e2e.c`) and skips `check_toolchain.sh`; `src/build_config.h` has the `WITH_CONFIG` fallback.
- `BUILD=dev` builds project code at `-O0` without `_FORTIFY_SOURCE` into separate `.dev.*` objects for faster iteration; default `BUILD=prod` remains the hardened `-O2` build used by CI. The vendored s7 parser is always `-O0` because it only parses config at startup. `make -j$(nproc) dev` sets `BUILD=dev` with the default toolchain and forwards extra goals such as `make -j$(nproc) dev tests`.
- `make lib` builds `libmogbus.a` (all project objects plus s7 and `src/util/arena_impl.c`) and `libmogbus.so` (`-shared -Wl,-soname,libmogbus.so`, `-pie` filtered out of `LDFLAGS`, relro/now kept, linked with `$(LIBS)`) from the same objects as the binary; `make`/`all` still builds only `./mogbus`. `make lib-check` builds `examples/embed_tcp.c` with only `-Iinclude` against both libraries (`.so` via rpath `$ORIGIN/..`), fails if `nm -D --defined-only libmogbus.so` shows anything but `mogbus_*` (plus linker `_init`/`_fini`/`_edata`/`_end`/`__bss_start`), and runs both examples; `make tests` depends on it. Project and s7 objects use `-fPIC -fvisibility=hidden` (not `-fPIE`; PIC is valid in the PIE binary), and the public header `include/mogbus.h` is the only API surface (`MOGBUS_API` exports). The test binary leaves `src/util/arena_impl.o` out because `vlib/vtest.c` has its own `ARENA_IMPL`. See `docs/user/library.md`.
- `make python` builds `libmogbus.so` and copies it to `python/mogbus/` (gitignored); `make python-tests` runs `python3 -m unittest discover -s python/tests` against the built library via `MOGBUS_LIB`. `python/` is a `ctypes`-only package (`mogbus/_lib.py` loads the library and declares the C structs/signatures, `core.py` is the API; one `RLock` per context serializes every call because the C library is not thread-safe, and `Server.start()` steps on a background thread). Keep it in sync with `include/mogbus.h` (struct layouts live in `_lib.py`; a test compares the `ServerOptions` defaults with the C ones). `examples/python/embed.py` runs in CI through `make python-examples` (the pytest example `test_device.py` does not; pytest is not a dependency). `tools/mogbus_import.py` (stdlib-only CSV/pymodbus importer, `docs/user/importing.md`, examples in `examples/import/` with committed `.scm` outputs) is tested by `python/tests/test_import.py` (needs `./mogbus` for the `--check` cases, so the CI `python` job builds the binary). CI job `python`; `python/**` is a CI input in `ci.yml` and `tools/ci_changes.sh`. See `docs/user/python.md`.
- `make dist` (prod only) builds and writes `dist/mogbus-<version>-linux-<arch>.tar.gz`, `.spdx.json` (via `tools/gen_sbom.sh`, plain shell) and `SHA256SUMS`; `make clean` removes `dist/`. `.github/workflows/release.yml` (tags `v*`, must equal `MOGBUS_VERSION_*` in `include/mogbus.h`; `workflow_dispatch` is a dry run) builds x86_64 and aarch64, runs tests, publishes the release and attests provenance; pin new actions by commit SHA. See `docs/dev/release.md`.
- Builds must stay bit-for-bit reproducible (`tools/check_reproducible.sh`, CI job `reproducible`): keep `REPRO_FLAGS` (`-ffile-prefix-map`) on every compile of shipped objects, sorted source lists, `ar rcsD`, no `__DATE__`/`__TIME__`/clock or absolute paths in artifacts, and the git revision (`MOGBUS_GIT_REVISION`) only in `src/main.c`. `mogbus --version`/`-V` prints `mogbus X.Y.Z (<revision>)`.
- `make tests` builds `./mogbus` (needed by integration tests) and `./mogbus-tests`, then runs the tests through `tools/run_tests.sh`.
  - Do not trust a plain whole-suite run of the vtest binary for pass/fail: vtest exits 0 for whole suites even on failure. `tools/run_tests.sh` runs each test individually and fails correctly. Tests run one per process in parallel with `RUN_TESTS_JOBS` workers (default `nproc`, via `xargs -P`), slowest first using the previous run's durations in `BIN.times` (gitignored, removed by `make clean`); integration tests must pick free ports (`ts_free_port`) and never share fixed resources, since any two tests may run at once.
- `make fuzz` builds libFuzzer harnesses `tests/fuzz/fuzz_*.c` (clang `-fsanitize=fuzzer,address,undefined`, compiled directly from `src/modbus`, `src/device`, `src/util` and a few `src/net` files into `build/fuzz/`); `make fuzz-run FUZZ_SECONDS=N` seeds and runs each (`tools/run_fuzz.sh`, CI job `fuzz` at 60 s). New `tests/fuzz/fuzz_NAME.c` files are picked up automatically; keep harness invariants true to the spec (e.g. CANopen extended exceptions are longer than 2 bytes). `tests/robustness.c` covers garbage and fragmented frames on every network transport; `tools/loadtest.py` is the load/stability tool (CI: 32 clients, 5 s); `examples/interop/pymodbus_interop.py` is the pymodbus interoperability check (CI job `interop`, pinned `pymodbus==3.8.6`).
- `make asan` builds/runs sanitizer tests (`ASAN_OPTIONS=detect_leaks=0` is intentional here; vendored `third_party/s7` is compiled without sanitizers). ASan builds include `float-cast-overflow`.
- CI-equivalent checks: `make`, `make tests`, `for p in profiles/*.scm; do ./mogbus --check "$p"; done`, `make asan`. The no-TLS job runs `make WITH_TLS=0`, `make WITH_TLS=0 tests`, the same profile checks and `tools/check_doc_examples.sh` without installing OpenSSL, plus `make WITH_CONFIG=0 tests` and `make WITH_CONFIG=0 WITH_TLS=0 tests`. CI uses the runner's clang with the Makefile defaults in the prod, no-TLS and dev jobs, installing ccache and mold in those jobs; the analyzer job installs clang-tools and uses clang `scan-build` (excluding vendored s7) with plain linker flags because its bundled clang does not accept `-fuse-ld=mold`; no GCC-only flags remain. Keep all profile checks passing in both builds when changing config parsing/validation or device behavior.
- CI runs only when code changes: `ci.yml` path filters skip pushes that touch neither code nor the files the api-docs job builds (`LICENSE`, `python/README.md`, ... are not watched; of the workflows only `ci.yml` itself is; `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `NOTICE.md`, `AGENTS.md` and `docs/**` are watched because they are pages of the generated site), and its first job `changes` (`tools/ci_changes.sh BASE HEAD`) skips the build/test jobs when C files changed only in comments (comparing `gcc -fpreprocessed -E` output) or only packaging files changed: `api-docs` runs for any C, Doxyfile, Markdown page, `docs/**`, Doxygen theme or `tools/check_doc_briefs.sh` change, `docker` for code or `Dockerfile`/`.dockerignore`/`deploy/**` changes. When adding a CI input (a new top-level file or directory the build reads), add it to both the path filters and `ci_changes.sh`.
- `./mogbus --check <config.scm>` validates a config without starting the server; when TLS is enabled it creates (and destroys) a TLS context, so missing/mismatched files and bad ciphers fail with exit status 1 instead of printing `config OK`.
- `Dockerfile` (multi-stage, Debian trixie pinned by tag and digest, runs as UID/GID 10001), `.dockerignore`, `deploy/docker/mogbus.scm` (container default config, binds `0.0.0.0:1502`), `deploy/docker-compose.yml` and `deploy/kubernetes/mogbus.yaml` are covered by the CI `docker` job (build, hardened run with `--read-only --cap-drop ALL`, wait for the Docker health status, register read, PID 1 uid/caps check, `docker stop` exit 0 under 8 s, `docker compose config`); no local Docker daemon is needed for anything else. When bumping the base image, update tag and digest in both `FROM` lines and the `base.name` label. See `docs/user/deployment.md`.
- After every push, check CI (`gh run list`/`gh run watch`) and open GitHub issues (`gh issue list --state open`). If an open issue needs handling, finalize the current push, pause the current loop, handle issues sequentially (branch/worktree, implement/test/review/fix/reverify/merge/cleanup/push, checking CI and open issues after each push), then resume the previous loop.

## Architecture & behavior (non-obvious)
- Main flow: `src/config/*` reads the Scheme config as data (via s7 `read`, not evaluation) and builds devices. TCP (`src/net/tcp_server.c`, single-thread `poll`, max 32 clients), RTU (`src/net/rtu_server.c`, single-thread `poll` on one byte-stream fd), ASCII (`src/net/ascii_server.c`, single-thread `poll` on one byte-stream fd, CRLF-delimited frames), ASCII-over-TCP (`src/net/ascii_tcp_server.c`, single-thread `poll`, max 32 TCP clients, same CRLF framing), RTU-over-TCP (`src/net/rtu_tcp_server.c`, single-thread `poll`, max 32 TCP clients, RTU framing), Modbus UDP (`src/net/udp_server.c`, single-thread `poll` on one datagram socket, one MBAP ADU per datagram, replies to the source address), ASCII-over-UDP (`src/net/ascii_udp_server.c`, same socket layer, exactly one `:`...CRLF ASCII frame per datagram), and RTU-over-UDP (`src/net/rtu_udp_server.c`, same socket layer, exactly one RTU frame per datagram, no t3.5/t1.5 timing, frame handling via `rtu_framer_handle_frame`) decode transport frames, then dispatch PDUs through `src/modbus/pdu.c` to `src/device/*`. `src/modbus/rtu.c` owns CRC-16 and RTU frame encode/decode; `src/modbus/ascii.c` owns hex/LRC encode, decode and delimiter scanning. Dependency direction: `server -> net -> modbus -> device -> util`, `config -> device -> util` (config only includes `server/server_mode.h`), `server_config -> server, config`, `main -> api` (`src/main.c` includes only `mogbus.h`, checked by `tools/check_deps.sh`), `api -> server_config, server, config, net, modbus, device, util` (`src/api/mogbus.c` implements the public C API in `include/mogbus.h`; it is the top layer and nothing includes it). Each transport server is a caller-owned struct with `X_server_init/step/stop/close` plus a `run` wrapper and no global state; `src/api/probe.c` implements `mogbus_probe` (the client side of `mogbus --health`: one FC 08 sub 0x0000 echo to the first configured device over tcp/udp/rtu-tcp/rtu-udp/ascii-tcp/ascii-udp, wildcard binds probed via loopback, TLS only connect-tested, an exception reply counts as healthy, serial/PTY/fd modes rejected with `health check needs a network mode`; no allocation, blocking with a deadline); `src/server/server.{h,c}` is the config-independent facade over all eight transports (`server_options_t`, PTY/serial open, `*_fd` modes for host-owned fds) and `server_config.c` is the only adapter from `config_t`; `src/main.c` is a pure client of the public API (linked against the variant-tagged static library, e.g. `libmogbus.dev.a`; `libmogbus.a` in prod) and keeps CLI parsing, SIGINT/SIGTERM/SIGPIPE handling (calls `mogbus_server_stop`), the `--check` summary and printing, and the net layer installs no handlers (see `docs/dev/architecture.md`). Headers live next to `.c` files. TCP-family listeners (`tcp`, `rtu-tcp`, `ascii-tcp`) and UDP sockets (`udp`, `rtu-udp`, `ascii-udp`) bind to
`127.0.0.1` by default; `0.0.0.0` is explicit opt-in for remote access. See `docs/dev/architecture.md`.
- `src/net/net_obs.{h,c}` holds per-server metrics, the structured request log line and the HTTP `/healthz`/`/readyz`/`/metrics` endpoint (`(server (http ...))`); transports must poll through `net_poll()` and record requests via `net_handle_pdu()`/`net_obs_request()`. `--log-format json` / `mogbus_set_log_format` switch logs to JSON. `(http (control on))` / `http_control` (off by default, WARN at start, no authentication) enables `/api/` in `src/net/net_control.{h,c}`: JSON read/write of tables (client-write semantics except that read-only points are writable), host-side `/value` set, and runtime fault set/clear validated by `fault_check()` (shared limits with the config loader; faults persist across device restart, percent only, no schedules); it is reachable without sockets through `net_obs_http_feed()` (fuzzed by `tests/fuzz/fuzz_http.c`) and counted in `mogbus_control_requests_total`.
- `src/net/net_tcp_pool.{h,c}` shares listen setup, accept backoff, peer formatting, free-slot lookup, idle sweeps and the common poll-table skeleton across the three TCP transports; `src/net/net_udp.{h,c}` is the shared datagram layer for the UDP transports (bind, `recvfrom` with `MSG_TRUNC` drop of empty/oversized datagrams, `sendto`, peer text, and a fixed 16-slot table of delayed responses so the `delay` fault never blocks), reused by the ASCII/RTU-over-UDP servers with their own framing; `net_mbap_respond` in `net_common` is the MBAP unit routing/PDU/fault path shared by `tcp_server` and `udp_server`; `net_tls_conn_t` in `net_tls`/`net_tls_stub` owns the SSL handle, handshake/want flags and handshake deadline, so servers only query TLS state through `net_tls`.
- Device model: points are static, ramp, model (`sine`, `lag` towards a number or point, optional `noise` and `degradation` (drift, noise growth, stuck, fail) on any numeric behaviour; stateless except lag and stuck, evaluated in `model_value()`, frozen by client writes, reset by restart; `fail-after-ms` makes `device_range_failed()` turn FC 01/02/03/04/23 and user-defined `(registers ...)` reads into exception 04 and survives writes until restart; machines cannot drive them) or machine-driven. Register types are u16/s16/u32/s32/float32/u64/s64/float64 and strings (`(type string) (length N)`, N registers of ASCII, holding/input and static only, rejected as machine targets/inputs), with `(word-order ...)` for 32/64-bit and `(byte-order little)` swapping the bytes of every register; values are f64 in ramps/models/machines (u64/s64 above 2^53 round) but a static u64/s64 integer is kept exact. 4 Modbus tables of 65536 addresses each (coil/discrete/input/holding). Only configured points exist; an address with no owner is intentionally undefined and reads/writes to undefined/out-of-table targets return Modbus exception `0x02` (not a missing implementation). `(access read-only)` (coil/holding only, rejected on input/discrete; `point_t.read_only`, `mogbus_point_t.read_only`) makes every Modbus write touching the point fail with exception `0x02`: `pdu.c` writes go through `device_client_write()` (FC 22/23 pre-check with `device_range_writable()`), while `device_write()` stays the host path (`mogbus_device_write`, HTTP control raw PUT, machines) and ignores it. `device_tick` is computed at request time (no background thread).
- Modbus support is intentionally limited to FC `01,02,03,04,05,06,07,08,0B,0C,0F,10,11,14,15,16,17,18,2B/0E,2B/0D`. The simulator itself emits exception codes `01,02,03,0B`; the remaining standard codes (`04,05,06,07,08,0A`) are available only through fault injection (`09` is reserved): `04` also via `(kind sensor-disconnect)`, the others via `(fault (kind exception) (code N))`. Fault kinds are `delay`, `drop`, `exception`, `corrupt`, `disconnect`, `restart` and `sensor-disconnect`; `(fault ...)` is repeatable with at most one definition per kind, each fires by `percent` or a non-repeating schedule (max 8 steps, canonical rules in `docs/user/config-reference.md`), `corrupt` mode is `pdu` (default), `register` or `checksum` (checksum rejected in `tcp` and `udp`, where MBAP has no checksum), and `disconnect` is valid only in `tcp`, `rtu-tcp` and `ascii-tcp` modes (it implies drop and closes the client; `udp`, `ascii-udp` and `rtu-udp` have no connection and reject it). Faults never change request processing, but they no longer only affect the response: `restart` resets device state after the response is built, and `sensor-disconnect` turns successful FC 02/04 reads into exception 04. Other FCs get exception 01 unless a device defines them with `(function-code CODE ...)` (user-defined codes 1-127 that are not built in: up to 8 per device, up to 16 `(on "HEX PREFIX" ACTION)` cases matched in order on the request data, actions `reply`/`echo`/`exception`/`registers`/`no-response`, unmatched request is exception 03; built-in codes cannot be redefined; they go through the same fault, listen-only, counter and metrics handling; config-only, listed by `--check` and `mogbus_device_info`; see `docs/user/config-reference.md`). TCP uses MBAP (optionally TLS-wrapped in `mode tcp` via `(server (tls ...))`, default port 802, client certificates required by default, `(tls (handshake-timeout-ms N))` closes unfinished handshakes after N ms (default 10000) independently of idle timeout, TLS closes send a one-shot nonblocking best-effort close_notify without waiting, ungraceful drops with an empty OpenSSL error queue are treated as EOF, authenticated client subjects are logged at INFO and the configured CA is advertised to clients, no role-based certificate authorization; plaintext default stays 1502); RTU uses `[addr][PDU][CRC lo hi]` over PTY/device byte streams; RTU-over-TCP uses RTU frames over TCP sockets as an explicit separate `(server (mode rtu-tcp))` transport. `(server (mode udp))` is Modbus UDP: one MBAP ADU per datagram on a UDP socket (default port 1502, loopback bind by default), unit routing and unknown-unit exception `0B` as in `tcp`; a datagram whose protocol id is not 0 or whose MBAP length does not match the datagram size, an empty datagram and one longer than 260 bytes are dropped silently (DEBUG log); replies go to the source address; delayed responses wait in the fixed table (full table drops the response with a WARN); it accepts only `mode`, `port`, `bind` and `seed`, so `tls`, `idle-timeout-ms`, serial/RTU timing options and `broadcast-execute` are rejected at load time. `(server (mode ascii-udp))` carries ASCII over UDP: each datagram must be exactly one complete `:`...`CR LF` frame (a missing CRLF, trailing or leading bytes, or a second frame make it malformed: no reassembly, no resync, no partial-frame timeout), request semantics and the per-malformed-frame FC08 `0x000C` count are those of `ascii-tcp`, replies go to the source address (uppercase hex, one frame per datagram), empty and oversized (> 515 bytes) datagrams are dropped before decoding without counting, unit ids follow RTU/ASCII rules (1-247), and it accepts only `mode`, `port` (default 1502), `bind` and `seed`. `(server (mode rtu-udp))` carries RTU over UDP: each datagram (max 256 bytes) must be exactly one RTU frame (two frames or trailing bytes reject it whole; a rejected datagram of 4-256 bytes counts one FC08 `0x000C` error on every device), request semantics are those of `rtu-tcp` (bad CRC/unknown unit/broadcast silent, `broadcast-execute` allowed), replies go to the source address, unit ids are 1-247, and it accepts only `mode`, `port` (default 1502), `bind`, `seed` and `broadcast-execute` (`baud`, `frame-gap-ms`, `strict-t15` are rejected). ASCII uses `:` + uppercase hex `[addr][PDU][LRC]` + `CR LF` over PTY/device byte streams and, in `(server (mode ascii-tcp))`, over TCP byte streams (not MBAP/Modbus TCP); it is CRLF-delimited with no t3.5/t1.5 timing, accepts lowercase hex on RX, and malformed/bad-LRC/unknown/broadcast frames produce no response and never reach PDU dispatch. ASCII resynchronizes at a second colon before the terminator, waits for the LF when a trailing CR ends a read, ignores CR/LF/space between frames without counting errors, drops a partial frame with no byte for 1 s, and counts each rejected/undecodable frame as one FC08 `0x000C` communication error on every device. Serial ASCII ttys default to 8N1; `(server (data-bits 7) (parity even) (stop-bits 1))` selects 7E1. `ascii-tcp` accepts only `mode`, `port`, `bind`, `seed`, and `idle-timeout-ms`; serial line options and `broadcast-execute` are rejected there. FC08 `0x0003` is rejected with exception 03 so `CR LF` framing cannot be changed per device. RTU inter-frame boundaries use baud-derived t3.5 when baud is known (config or tty), `frame-gap-ms` as an explicit override, or 20 ms default fallback when baud is unknown. In baud-derived auto mode, optional `(server (strict-t15 on))` enables a best-effort intra-frame t1.5 discard heuristic for RTU byte streams only; it is never applied to RTU-over-TCP because TCP read() boundaries do not reflect UART character timing. Bad CRC, unknown RTU unit, and broadcast (0) produce no RTU response; opt-in `(server (broadcast-execute on))` executes unit-0 requests on every configured device (default off, still no response, RTU transports only (`rtu-pty`, `rtu-device`, `rtu-tcp`, `rtu-udp`) — never MBAP/TCP or ASCII, where the option is rejected at load time). Writes are all-or-nothing and only valid for coils/holding registers and configured file records (FC 21). See `docs/user/modbus-support.md` and `docs/user/config-reference.md` before changing protocol/config semantics.

## Repo constraints
- Plain C (gnu11), Linux-only (`poll`, `accept4`, vlib mmap arenas). Default build prefers clang (then gcc, then cc) and the default linker, with ccache and mold added independently when available and supported, and is hardened with `-Wall -Wextra -Werror -Wformat=2 -Wshadow -D_FORTIFY_SOURCE=2 -fstack-protector-strong -fPIC -fvisibility=hidden` (s7 gets only `-fPIC -fvisibility=hidden -fstack-protector-strong` with its own relaxed flags) and linked with `-pie -Wl,-z,relro,-z,now`, plus `-fuse-ld=mold` when probed successfully; `CC`, `CFLAGS`, and `LDFLAGS` can be overridden from the environment or command line.
- No `malloc/free/new/delete` in project code; use vlib arenas (`ARENA_*`). `src/main.c` owns no arenas (the library context does); request handling must not allocate per request. `ARENA_IMPL` is defined only in `src/util/arena_impl.c` (part of the library) and `vlib/vtest.c` (the test binary excludes `arena_impl.o`). The public API allocates its context, devices and server slots from a per-context arena.
- `third_party/s7` and `vlib/` are vendored dependencies: do not “fix” style/warnings there; s7 is built with relaxed flags and excluded from sanitizers (known UBSan issue upstream in vendored version). `make commands` regenerates `compile_commands.json` via `bear` if needed.
- `src/*.c` are discovered recursively and `tests/*.c` by wildcard in the Makefile; adding files in those locations is picked up automatically.

## Style & scope
- Prefer the smallest change that solves the task; less is more. Avoid unnecessary abstraction, not optimization.
- Prefer fat structs over many small structs that are only used once inside a bigger struct. If a small struct belongs only to a bigger one, define it inside that bigger struct, e.g. `struct big { struct small { int a; }; /* other fields */ };`.
- Functions don't have to be short; they should do the job they need to do. If a small helper is only used once, prefer inlining it in the larger function. Inline tiny reused helpers when practical and clear.
- Multi-step `if`/`else if` conditions (three or more sub-conditions joined by `&&`/`||`) must be written one sub-condition per line, operator at the end of the line, continuation lines indented 4 spaces past the `if`:
  ```c
  if (a &&
      b &&
      c)
  ```
  A parenthesized group counts as one sub-condition.
- For enum-like groups of related constants, prefer enums over `#define` macros.
- Booleans don't need an `is_` prefix when the name is already clear (e.g. `log_verbose()`).
- Add comments only where logic is non-obvious or a constraint is easy to miss; do not comment routine changes. For complex behavior, add a short comment.
- Doc comments follow Doxygen (see `docs/dev/architecture.md`, Coding rules): `/** @file @brief */` at the top of every source file, `/** @brief One sentence. Details. */` above types/functions/macros, `/**< */` for members, `@name`/`@{ @}` for a comment that covers several declarations, full `@param`/`@return` for public `include/mogbus.h` functions only. Comments inside function bodies stay plain `/* */`. Do not add doc comments to self-explanatory members just for coverage. `make api-docs` (CI job `api-docs`) must stay warning-free. Typedefs: group all forward typedefs (`typedef struct x_t x_t;`, enums, unions) at the top of the file after the includes, never combine `typedef struct x_t { ... } x_t;`, and put the brief directly above the `struct x_t {`/`enum x_t {` definition (anonymous enums keep their brief above them; function-pointer and opaque typedefs keep their own brief). `tools/check_doc_briefs.sh` (run by `make api-docs`, needs `python3`) fails for any file, struct, union, enum, opaque or function-pointer typedef without a brief. The site theme (doxygen-awesome-css) is vendored in `third_party/doxygen-awesome-css/` and `docs/doxygen/header.html` is the stock header of `doxygen -w html` plus the theme scripts; regenerate it from the current Doxygen version when upgrading Doxygen. Markdown links between pages must be relative `.md` links; links to files that are not pages (profiles, sources, directories) must be absolute `https://github.com/BolvicBolvicovic/mogbus/blob/main/...` URLs because Doxygen fails on unresolvable relative links. - When behavior changes or a new user-facing/config/protocol behavior is added, update the relevant docs (`README.md`, `AGENTS.md` and `docs/` as applicable) instead of adding explanatory comments everywhere. `docs/user/` is for people who run, configure, embed or deploy mogbus (config reference, profiles, Modbus support, library API, deployment) and ships in the release tarball; `docs/dev/` is for contributors and maintainers (architecture, release process). Keep build internals, CI and release mechanics out of `docs/user/`.
- In reviews, inspect tests against intended behavior/spec; do not accept tests weakened or adapted to fit an incorrect implementation.
